---
name: reach-submit
description: Use when the student wants to submit their slice, submit it again before the due time, or asks whether a submission was received.
---
Offer to submit once `reach qualify` has passed: tell the student they can ask you to submit this part whenever they are ready, that it sends the work to their instructors and saves a ZIP of all their work for the assignment in their Downloads folder, that to receive credit for this coursework they must also upload that ZIP to Blackboard (or the system Reach names), and that they can submit again until the due time (the last one counts).
Before submitting, run `reach part`: every question must be answered in the student's own words. If one is missing, ask it first.
`reach submit` works only after `reach qualify` passed on exactly the files you have now; if it refuses, run `reach qualify` first. Run `reach submit` (or the reach_submit tool). Reach asks the student itself: when it answers with Reach's question, relay it word for word and wait. Reach captures the student's answer itself. Never answer the question for the student, and never submit after a no.
When Reach then says the student said yes, run `reach submit` again once, as it says. Most of the time the receipt comes back straight away; tell the student in plain words what was received, the receipt number and the time, where the ZIP of their work was saved, and whether and until when they can submit again. After every submission, say again in your own words that the student must also upload that ZIP to Blackboard (or the system Reach names) to receive credit; the submission to rEach alone does not give credit.
If the ZIP was not saved (Reach says it was too large or could not be saved), or the student lost it, run `reach submit archive` (or the reach_submit tool with archive true) to make it again for an assignment that has been submitted, and tell them it still has to be uploaded to Blackboard.
The student can have a ZIP of their work for an assignment at any point, submitted or not: when they ask, or when `reach qualify` says the checks could not run and recommends it, run `reach submit archive --assignment <assignment>` (or the reach_submit tool with archive true and assignment). For work not submitted that ZIP is not a submission: tell the student in plain words that rEach has not sent it to their instructors, and that to hand it in another way they upload it to Blackboard (or the system Reach names) or send it to their instructor, saying the course's checks could not run when that was the reason. It works even while rEach is locked; then the student runs `reach submit archive` in a terminal. Reach refuses only when there is no work for that assignment on this computer, and during a timed test. For more than one assignment, `reach submit archive --course <course>` saves one course, `--extracurricular` the student's own code folder, and `--all` everything (or the reach_submit tool with archive true and scope course, extracurricular or all).
The student can also hand in unfinished work that has not passed `reach qualify`: run `reach submit --partial` (or the reach_submit tool with partial true) when they want that. Reach asks them itself, as for a full submission; relay its question word for word and submit only after their yes. Tell them in plain words that partial work goes to their instructor for review, is not graded automatically, and that they can still submit the finished work later. If Reach says the course server can't take partial work yet, offer the ZIP instead.
If Reach says the part is late, tell the student in plain words that it will be marked late, and that it can be submitted again, each one marked late, up to 50 submissions of the part in all. A submission after the due time is accepted every time and marked late; never tell the student a slice is closed for submission.
On Antigravity, Reach cannot ask for you: ask the same question in plain words, and run the command only after the student's yes.
If submit says the work is queued, run `reach receipts wait --submission <id>` when you have an id, or `reach sync` when you are back online, and tell the student it has not been received yet.
If submit says the work wasn't accepted, read the reason and the fix to the student in plain words.
When a grade receipt arrives, show the signed scenario results in plain words. A queued or received submission is not passed. If a result fails, use the reach-bug skill, pass `reach qualify` again, and submit the correction with the student's yes.
